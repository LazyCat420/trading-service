## Defect found and fixed by the baseline scan

`app/processors/quant_processor.py` **did not parse** at HEAD — a
`SyntaxError: unexpected indent` at line 114. The final conversion commit
(`5e4e1d0`) removed a `with get_db()` wrapper from `get_correlations()` and
never de-indented its body, orphaning lines 113–147 at the old level. Master's
copy of the file parses; the branch's does not, so the module could not be
imported at all.

Fixed by dedenting the orphaned block 4 spaces. Verified: the file parses,
`import app.processors.quant_processor` succeeds, and the function body is
structurally identical to master's apart from the intended Mongo conversion.

This is exactly what a static gate is for. 4,170 tests and 40 commits of
"complete pure MongoDB migration" did not surface a module that cannot be
imported; a parse-everything scan surfaced it on its first run.
